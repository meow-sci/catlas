# Procedural asset contract for KSA

Research is pinned to the supplied KSA build `2026.10.10.5554` in `ksa-game-assemblies/current/decomp` and the matching `ksa-linux/Content/Core` files. The browser generator in `src/lib/assets.ts` writes new pixel and mesh data; it does not ship or transform Core textures or models. Native runtime behavior still needs a game smoke test.

## Planet maps

`Content/Core/Astronomicals.xml` supplies rocky bodies with `Diffuse`, `Normal`, `Scattering`, `Surge`, `Height`, `BiomeIDMap`, and `BiomeControlMap` entries (Earth near lines 540–567 and Luna near 1910–1938). Gas bodies such as Saturn supply `Diffuse` without terrain maps (near line 4230). `KSA/AstronomicalTemplate.cs:166–209` checks that diffuse, normal and height textures are cubemaps; `KSA/BiomesReference.cs:92–104` similarly checks biome maps. `KSA/HeightReference.cs` maps normalized height to an XML `<Minimum Km>` and `<Maximum Km>`. `Content/Core/Shaders/DistantSphere.vert:63` samples height from the red channel.

The generator emits six-face uncompressed KTX2 images with full mip chains, ordered +X, −X, +Y, −Y, +Z, −Z under the [Khronos KTX2 specification](https://registry.khronos.org/KTX/specs/2.0/ktxspec.v2.html). Diffuse, normal, biome ID/control, scattering and surge use `VK_FORMAT_R8G8B8A8_UNORM` (37). Height uses `VK_FORMAT_R16_UNORM` (70), matching Core's uncompressed height format. Faces are contiguous inside a mip level; levels have 8-byte aligned offsets. `ktx-parse` and a distinct-face R16 test validate the writer's container structure.

The normal cubemap contains the neutral tangent-space normal (128,128,255) at every texel. This avoids face-seam orientation errors while the height cubemap carries geometric relief. `Content/Core/Shaders/Planet/Planet.frag:142–145` samples and decodes the normal map. The current CPU normal sampler supports BC5 only for its two-channel path (`RenderCore/TextureAsset.cs`, summarized in `docs/research/runtime-loader-audit.md`), so generated RGBA normals are a native testing point. Scattering and surge are generated six-face maps with conservative constant values; the game shader reads `scattering.rgb` and `surge.rgba` in `Content/Core/Shaders/Planet/Planet.frag:269–286`. This removes dependence on Core's default Hapke assets while leaving a photometric tuning opportunity.

The minimum terrain biome is one `Surface` biome. Its ID map has zero in all channels and its control map is `(255,0,0,0)`. `Content/Core/Shaders/Common/Planet.glsl:277–304` normalizes control weights and converts each normalized ID channel to a biome index. Authored occurrence colors are baked into diffuse pixels, while the single biome remains a safe renderer/material baseline. Procedural noise and crater evaluation use direction in 3D, so colors and heights meet across cube faces.

The generator also writes a 2D terrain material triplet: diffuse, neutral tangent-space normal, and AO/roughness/metal. The green ORM channel comes from the authored `surface.roughness` setting. A `Surface` `BiomeMaterial` uses this triplet for both `GroundMaterial` and `SlopeMaterial`. Without this declaration, `KSA/PlanetRenderer.cs:694–721` populates default zero material handles even when biome cube maps are present. The generated material therefore matters for close-range terrain as well as asset independence.

Terrain diffuse alpha is 255. In `Content/Core/Shaders/Planet/Planet.frag:231–246`, alpha selects the branch that multiplies the close-range detail by the global color cubemap; this keeps palette and occurrence colors visible at the surface. The XML height range is `[-seaLevel × elevation, (1 − seaLevel) × elevation]` kilometres, matching the browser preview's `(normalizedHeight − seaLevel) × elevation` displacement.

## Clutter and rings

`Content/Core/GroundClutter/GenericRockAssets.xml:4–30` shows the required mesh-atlas, ground-clutter material and clutter-object references. `KSA/ClutterObjectTemplate.cs:76–88` requires exactly five LOD declarations. The exporter repeats the generated mesh name in five levels. The generator writes a glTF 2.0 binary (`.glb`) with baked vertex positions, normals, UVs and tangents. `KSA/MeshAtlasFileReference.cs:26–45` registers meshes by glTF mesh name, so the XML `<Mesh Id>` must equal `<body.id>_RockMesh`. Generated diffuse, normal and AO/roughness/metal textures form the material set. The shader reads AO from red, roughness from green and metalness from blue (`Content/Core/Shaders/Planet/GroundClutter/Solid.frag:345–347`). A generated distribution PNG is referenced by each enabled ecotype; `KSA/ClutterEcotypeReference.cs` throws when it is missing.

`Content/Core/Astronomicals.xml:4261–4320` gives Saturn's ring format. The ring band and control textures are one-row PNGs. Its control red channel enables visible ring rocks, green controls volume thickness, blue controls overlay detail, and alpha is unused (the XML comment near line 4266 states this directly). `KSA/PlanetaryRingsReference.cs` requires `Volume` and `RingObjects`; `KSA/RingObjectsReference.cs` requires one to five valid mesh LODs plus a material. The same generated rock GLB and PBR images serve ring objects even when ground clutter is disabled. The ring band and control pixels, generated rock GLB, and material PNGs all come from the project's seed and settings.

All paths returned by `bodyAssetPaths()` are relative to the mod's content root. `generateBodyAssets()` returns the exact bytes for each path, so the exporter can compare every XML file reference against the archive before finishing it.
